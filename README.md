# Focus English Lab

2026년 1월 21일 이후 공개된 영어 능력시험의 과제 설명을 참고한 독립 연습용 웹 앱입니다. 모든 문제는 이 프로젝트를 위해 새로 작성했으며 공식·기출 문항이나 공식 채점 엔진을 포함하지 않습니다.

현재 앱 버전은 **0.1.54**입니다. 정식 1.0 이전에는 `0.MINOR.PATCH` 형식을 사용하고, 배포되는 기능·동작 변경마다 최소 패치 버전을 올립니다. 앱의 **설정** 화면 맨 아래에서 현재 실행 중인 버전을 확인할 수 있습니다.

## 실행

```bash
npm install
npm run dev
```

개발 서버를 켜면 Kokoro 모델도 서버에서 한 번만 준비됩니다. 생성된 WAV는 `.cache/tts/`에 저장되며 같은 문장과 화자는 다시 합성하지 않습니다. 첫 모델 다운로드와 첫 문장 생성은 백그라운드에서 진행되어 시험 시작을 차단하지 않습니다.

이 작업 폴더에는 모델이 `.cache/models/`에 미리 준비되어 있어 평소 실행 중에는 다운로드하지 않습니다. 모델 캐시를 직접 지운 경우에만 `npm run tts:download`를 한 번 실행하세요.

브라우저에서 표시되는 로컬 주소를 여세요. Speaking 연습은 마이크 권한이 필요합니다.

## 웹 버전과 휴대용 시험 데이터

GitHub Pages 배포 설정이 `.github/workflows/pages.yml`에 포함되어 있습니다. 저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 한 번 지정하면 `main` 브랜치가 갱신될 때 `https://aoml3245.github.io/focus-english-lab/`에 자동 배포됩니다. 로그인은 iPhone의 팝업 제한과 브라우저의 서드파티 저장소 제한을 피하기 위해 같은 Firebase 프로젝트에서 호스팅하는 `https://focus-english-lab-3245.firebaseapp.com/`으로 이어진 뒤 전체 화면 Google 인증을 사용합니다.

홈의 **시험 데이터** 화면에서는 다음 작업을 할 수 있습니다.

- 현재 또는 기본 1,360문항을 `.felpack.json`으로 내려받기
- 휴대폰·태블릿·다른 컴퓨터에서 같은 파일을 선택해 문제은행으로 사용하기
- 가져온 파일을 해제하고 기본 문제은행으로 복원하기

시험 데이터 파일은 브라우저 안에서만 읽고 외부 서버에 업로드하지 않습니다. 웹 버전의 Listening·Speaking도 브라우저 안에서 Kokoro 82M q8 모델을 실행하며, 처음 사용할 때만 약 90MB급 모델 데이터를 내려받아 브라우저 캐시에 저장합니다. Ollama Writing/Reading 보조 기능은 로컬 실행에서만 사용할 수 있습니다.

웹 앱과 공개 기본 단어장·단어 게임은 로그인 없이 열립니다. 직접 검수를 마친 기본 어휘는 1,000개 단위의 정적 조각으로 GitHub Pages에 배포하며, 현재 공개 체크포인트는 9,000개입니다. 학습 기록·진도·내가 만든 단어장은 기기에 먼저 저장되고, Google 계정으로 로그인한 경우에만 Firebase에서 계정별로 분리해 동기화합니다.

다른 사용자와 단어 목록을 함께 쓰려면 소유자가 **설정 → 개인 계정 및 기기 동기화 → 공유 코드 만들기**를 누릅니다. 상대방은 자기 Google 계정으로 로그인한 뒤 30분짜리 일회용 코드를 입력합니다. 그룹은 소유자와 상대방 두 명까지만 허용하며, 공유되는 것은 단어 목록뿐입니다. 각자의 학습 통계와 시험 기록은 서로 다른 사용자 문서에 저장됩니다.

시험 데이터 화면의 원형 **?** 버튼을 누르면 `.felpack.json` 최상위 구조, 8개 문항 유형별 필수 필드, 객관식 정답 번호 규칙을 볼 수 있고 전체 유형이 들어 있는 예제 파일도 내려받을 수 있습니다.

## 포함된 기능

- Reading → Listening → Writing → Speaking 순서
- 2,922개의 독창적인 문제은행과 매회 새로 구성되는 랜덤 세트
- `랜덤 전체 세트`: 객관식 문항마다 답을 제출한 즉시 정오답·정답·해설을 보여주고 피드백 중 타이머 정지
- `실전 모의시험`: 실제 시험처럼 진행 중에는 정답을 숨기고 전체 종료 후 결과와 해설 공개
- 섹션·유형별 집중 연습: Reading 3종, Listening 4종, Writing 3종, Speaking 2종을 각각 따로 선택하거나 섹션 전체 유형을 섞어 출제
- 945개 주제 묶음을 학술 지문·생활 안내·캠퍼스 대화·강의·이메일·토론·인터뷰 맥락으로 연결
- IELTS, Cambridge English, PTE Academic, Duolingo English Test의 공식 과제 설명에서 맥락 범주를 조사해 반영
- 환경·과학·공학·심리·경제·역사·예술·기술·보건·캠퍼스 행정 등 폭넓은 주제
- 문항별 타이머와 자동 이동
- Listening 이전 문항 복귀 제한
- ETS 공식 예시를 반영한 Writing 문장 구성: 5–8개의 섞인 단어·짧은 구 타일, 빈칸 슬롯, 일부 방해 타일
- 브라우저 TTS 오디오와 마이크 녹음
- Kokoro 82M 오픈소스 AI 음성, 대화 자동 배역, 미국식·영국식 음성 미리 듣기와 기본 음성 저장
- 시험 시작 전 TTS 엔진·선택 화자 워밍업, 테스트 문장과 첫 실제 음성 선행 합성, 실패 시 세션 단위 시스템 음성 대체
- `localStorage` 자동 저장·이어하기와 최근 50회 학습 기록
- 객관식 기반 연습 추정 결과
- 완료한 시험의 전체 문항·당시 답안·정답·해설 복습
- 시험별 랜덤 후보 포함/제외 선택: 제외한 세트의 문항은 기록을 보존한 채 이후 전체·섹션 랜덤 출제에서 제외
- 문제은행 문맥 어휘와 공개 사전 어휘 중 직접 검수를 마친 9,000개 공개 기본 단어장: 대표·문맥 뜻과 최대 3개의 품사별 주요 의미, 영영 정의·발음·CEFR·엄격한 동의어·예문·한국어 해석
- 문항 빈도와 B2–C2 난이도를 결합한 프로젝트 자체 학술 핵심 표시

- 로컬 Ollama LLM을 이용한 문맥별 한국어 뜻·유의어 3개·예문 해석 자동 정리

- 문장 미니게임: 문제은행 문맥 예문으로 영어→한국어 해석과 한국어→영어 영작을 번갈아 연습하고 정답 예시 즉시 확인
- 선택적 로컬 LLM 문장 평가: 의미 보존·문법·어휘·자연스러움 점검, 교정 설명과 개선 답안 제공
- Qwen 3.5 9B 로컬 Writing 코치: ETS 기준 0–5 연습 추정, 강점·기준별 진단·문장 교정·수정 계획·개선본·후속 질문

## 범위

전체 연습은 유형 비율을 유지한 55문항, 섹션 연습은 11–16문항을 문제은행에서 무작위로 선택합니다. 정식 다단계 적응형 출제는 포함하지 않습니다. Writing 코치의 점수는 학습을 위한 로컬 LLM 추정치이며 ETS 공식 점수가 아닙니다. 모든 문제는 공식 형식과 맥락 범주만 참고해 새로 작성했으며 어떤 시험의 공식·기출 문항도 아닙니다. 조사 근거는 [`research-sources.md`](./research-sources.md)에 정리했습니다.

전체 29,976개 작업 원본은 Git에서 제외한 `private/vocabulary.json`에 보관하며 로컬 개발 서버에서만 직접 제공합니다. 직접 검수와 구조 검사를 통과한 항목은 1,000개 경계마다 `public/data/vocabulary/`의 250개 단위 조각과 해시 매니페스트로 내보냅니다. 웹 배포는 이 공개 체크포인트를 로그인 없이 읽고, 개인 Firebase 단어장과 학습 기록은 별도 계층으로 유지합니다. 제3자 어휘 데이터의 출처·라이선스는 [`THIRD_PARTY_NOTICES.md`](./THIRD_PARTY_NOTICES.md)와 [`DATA_LICENSE.md`](./DATA_LICENSE.md)를 참고하세요.

현재 전수 검수는 로컬 LLM을 사용하지 않습니다. 각 항목의 대표 의미, 최대 세 개의 주요 의미, 품사, 엄격한 동의어, 예문과 한국어 번역을 직접 확인하고, 내용 해시가 일치하는 항목만 승인 장부에 기록합니다. WordNet의 상위어·하위어·관련어는 동의어로 취급하지 않습니다.

```bash
python3 scripts/direct_review_batches.py --status
python3 scripts/direct_review_batches.py --next 300
# 직접 검수·교정 및 테스트 후 현재 배치를 승인
python3 scripts/direct_review_batches.py --accept-current
# 승인 수가 1,000개 경계를 넘었을 때 공개 조각 갱신
npm run vocab:export:public
```

공개 내보내기는 승인 장부의 해시와 현재 데이터를 다시 대조하고, 마지막 1,000개 경계까지만 포함합니다. 조각별 SHA-256, 항목 수, 바이트 수는 `manifest.json`에 기록되며 테스트에서 모두 재검증됩니다. 작업 중인 미승인 배치, `private/`, Firebase 개인 데이터, 검수 장부와 캐시는 커밋하지 않습니다.

iOS Safari는 ONNX Runtime이 공식 지원하는 q8 WASM 경로를 최대 4개 스레드로 실행하고, 데스크톱의 지원 브라우저만 native WebGPU EP를 우선 사용합니다. 문제가 보고된 구형 JSEP 실행 경로는 사용하지 않습니다. 두 경로 모두 전용 Worker에서 실행됩니다. 화면을 나가거나 정지를 누르면 재생과 결과 전달은 즉시 끊고, 실행 중이던 ONNX 한 조각의 결과는 폐기한 뒤 다음 대기 조각부터 중단합니다. iOS WebKit에서 phonemizer의 eSpeak 압축 데이터 초기화가 끝나지 않던 `ReadableStream` 반복 코드는 호환 가능한 reader API로 빌드 시 패치합니다. 긴 문장은 모델 한도 안에서 내부적으로만 나누고 PCM 결과를 하나의 WAV로 이어 붙인 뒤 한 번에 재생하므로 문장 사이에 플레이어 전환 공백이 생기지 않습니다. 생성 음성은 IndexedDB에 최대 64MB 또는 200개 항목까지만 LRU 방식으로 보관합니다. 음성 설정에서는 모델 다운로드, 음소 변환, ONNX 추론, 첫 재생 시간을 단계별로 확인할 수 있습니다. 모델 로딩이나 재생이 불가능한 환경에서는 자동으로 기기의 영어 음성 합성 기능을 사용합니다.

모의시험·섹션 연습·이어하기는 모두 시작 전 확인 화면을 거칩니다. 이 화면에서 선택한 TTS 엔진을 초기화하고 필요한 화자를 워밍업하며, 테스트 문장과 선택 세트의 첫 음성 문항을 미리 합성합니다. 준비 중에도 시험을 시작할 수 있고, 준비 완료 후에는 짧은 음성 테스트를 직접 들을 수 있습니다.

읽기 도우미는 기본적으로 `http://127.0.0.1:11434`에서 실행 중인 Ollama의 `translategemma:latest`를 사용합니다. 로컬 모델이 꺼져 있어도 기존 어휘는 내장 사전 뜻으로 즉시 확인할 수 있습니다. 지문에서 `내 단어장에 넣기`로 저장한 단어와 생성 결과는 로컬 브라우저에 즉시 보관되고 로그인 계정의 비공개 Firebase 문서에도 동기화되며, 단어장 화면의 `내가 만든 단어장` 필터에서 다시 볼 수 있습니다.

Writing 코치는 같은 Ollama 서버의 `qwen3.5:9b`를 기본으로 사용합니다. 16GB Apple Silicon 환경에서 품질과 메모리 사용량의 균형을 고려한 선택이며, 설치 명령은 `ollama pull qwen3.5:9b`입니다. 평가·대화 중에는 시험 타이머가 자동으로 멈추고 결과는 문항별로 브라우저에 저장됩니다.
